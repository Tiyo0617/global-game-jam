## 2. 环境准备（一次性操作）

> 以下所有步骤每人**自己电脑**上都要做一遍，缺一不可。

### 2.1 安装 Git for Windows

1. 打开 <https://git-scm.com/download/win>，下载安装包
2. 一路点"下一步"，**所有选项保持默认**即可
3. 安装完成后验证：按 `Win + R` 输入 `cmd` 回车，在命令行里输入：
   ```
   git --version
   ```
   如果能显示版本号（如 `git version 2.4x.x`），说明安装成功。

### 2.2 注册并登录 GitHub 账号

1. 打开 <https://github.com>，注册账号（已有账号跳过）
2. 注册完成后，把**你的 GitHub 用户名**发给仓库主，让他把你添加为协作者
   （不添加的话你只能下载代码，不能上传改动）
3. 在浏览器里保持登录状态

### 2.3 安装 Godot 4.5.1 .NET 版（最容易踩坑！）

> ⚠️ **本项目是 C# 项目，必须装 .NET 版 Godot。** 装成标准版的话，项目会打开失败或报脚本错误。

1. 打开 Godot 官网下载页：<https://godotengine.org/download/windows/>
2. **一定要选择带 `.NET` 标识的版本**（`.NET` 版本，文件名形如 `Godot_v4.5.1-stable_mono_win64.exe`）
   - 特征：文件名里有 **`mono`**
   - 不要下载普通的 `Godot_v4.5.1-stable_win64.exe`（那个是标准版，不支持 C#）
3. 下载后解压，双击运行。首次打开会提示导入，直接确认即可

**验证是否装对**：打开 Godot → 新建项目界面右上角或"项目管理器"标题栏，能看到 **Godot Engine v4.5.1.stable.mono.official** 这样的字样（注意 `mono`），或者能正常打开本项目的 `project.godot`。

### 2.4 安装 .NET SDK 8.0

C# 脚本编译需要 .NET SDK，不装的话项目里的 `.cs` 脚本会编译报错、游戏无法运行。

1. 打开 <https://dotnet.microsoft.com/download/dotnet/8.0>
2. 下载 **SDK**（不是 Runtime），选 Windows x64
3. 安装后验证：命令行输入
   ```
   dotnet --version
   ```
   显示类似 `8.0.x` 的版本号即成功。

### 2.5 验证环境（强烈建议按顺序自查）

| 检查项 | 命令 / 操作 | 预期结果 |
|---|---|---|
| Git | `git --version` | 显示版本号 |
| .NET SDK | `dotnet --version` | 显示 `8.0.x` |
| Godot 版本 | 打开 Godot | 标题带 `mono` / 能打开本项目 |

**全部通过后，再进入下一步。**

## 3. 克隆项目（一次性操作）

把 GitHub 上的项目完整复制到自己电脑上。

### 方法一：VS Code 图形化操作（推荐，最直观）

1. 打开 VS Code
2. 按 `Ctrl + Shift + G` 打开**源代码管理**面板
3. 点面板上的 **Clone Repository**（克隆仓库）
4. 输入仓库地址：`https://github.com/Tiyo0617/ggj`，回车
5. 选择存放位置：**建议建一个英文路径的文件夹**，例如 `D:\godot_work`（避免中文/空格路径）
6. 等待下载完成，右下角提示后点 **Open**（打开）

### 方法二：命令行

```bash
git clone https://github.com/Tiyo0617/ggj.git
```

### 首次打开项目（重要）

1. 用 Godot 打开克隆下来的 `project.godot`
2. 首次打开会重新导入资源、生成缓存，属**正常现象**，耐心等待
3. 如果是 C# 项目，Godot 顶部菜单会出现 **Build**（构建）按钮，点一下让它编译
4. 按 `F5`（或点运行按钮）能跑起来，就说明环境全部正确

## 4. 日常协作流程（每次必看）

> **核心口诀：先拉后改，先拉再推。**
> 意思是：开始干活前先"拉取"最新代码；提交上传前再"拉取"一次，确保没有覆盖别人的改动。

每次干活的完整流程（VS Code 操作）：

```
① 开工前：Ctrl+Shift+G → ...（菜单）→ 拉取（Pull）
		↓
② 专心改自己的文件（见第 5 章分工）
		↓
③ 改完提交：
   源代码管理面板 → 改动文件点 + 号（暂存）
   → 顶部输入框写明"改了什么"（如：添加玩家移动）
   → 点 ✓（提交）
		↓
④ 上传前再拉取一次：... → 拉取（自动合并队友的新改动）
		↓
⑤ 上传：... → 推送（Push）
```

**每次提交都要写清楚的说明文字**，这是你们的"改动日记"，写不清后面出问题没法查。

> 💡 提交信息示例：
> - ✅ `添加玩家移动和跳跃`
> - ✅ `修复碰撞检测 bug`
> - ❌ `update` / `aa` / `111`

## 5. 文件分工规则

**原则：每个人只动自己负责的文件，尽量不碰别人的。** 这是避免冲突的最有效手段。

### 当前项目结构

```
ggj/
├── project.godot        # Godot 项目配置（一般不需要手动动）
├── ggj.csproj / ggj.sln # C# 工程文件（不用动）
├── icon.svg             # 项目图标
├── UI/                  # 界面场景与脚本
│   ├── Main.tscn        # 主菜单场景
│   ├── Map1.tscn        # 地图/游戏场景
│   ├── Team.tscn        # 作者团队页
│   └── Begin.cs         # 开始按钮脚本
├── Scripts/             # 游戏逻辑脚本目录
├── assets/              # 美术/音效素材目录（放这里）
├── .gitignore           # Git 忽略规则（不用动）
└── .gitattributes       # 换行符规则（不用动）
```

### 建议分工（示例，按实际人员调整）

| 队员 | 负责文件 | 说明 |
|---|---|---|
| 主程 | `UI/Main.tscn`、主流程、`Scripts/` | 项目核心，改动前在群里打招呼 |
| 程序 B | `UI/Map1.tscn` + 对应脚本 | 游戏玩法 |
| 程序 C | `UI/Team.tscn`、`UI/Begin.cs` | 界面与交互 |
| 美术/音效 | `assets/` 全部素材 | 图片、音乐、音效 |

### 雷区警告

- ⚠️ **`Main.tscn` 可能被多人引用**：谁改了它，改完立刻推送，并**在群里说一声**
- ⚠️ **`.gitignore` / `.gitattributes` / `.csproj` / `.sln` 不要动**，除非管理员说明
- ⚠️ **`.godot/` 文件夹是本地缓存**，永远不要提交它（已被 .gitignore 忽略，你也不用手动删）

## 6. 遇到冲突怎么办

### 冲突是什么？

两个人同时改了**同一个文件的同一行**，Git 不知道听谁的，就会停下来要你做决定。**只要按第 5 章分工走，冲突几乎不会发生**；万一发生了也别慌：

### 解决步骤（VS Code）

1. 推送/拉取时提示 `CONFLICT`（冲突），打开报错的冲突文件
2. VS Code 会进入**合并视图**，文件里出现 `<<<<<<< HEAD ... ======= ... >>>>>>>` 标记
3. 在编辑器顶部选择：
   - **Accept Current**（保留你的版本）
   - **Accept Incoming**（保留对方的版本）
   - **Accept Both**（两个都保留）
   - 或手动编辑，把冲突标记 `<<<<<<<` / `=======` / `>>>>>>>` 删掉，保留正确内容
4. 保存文件 → `Ctrl+Shift+G` → `+` 号暂存 → 填写说明 → 提交 → 推送

### 拿不准保留哪边？

把冲突内容复制下来，发给 CodeBuddy AI 问："这个冲突该怎么合并？"，AI 会帮你分析。

## 7. 常见问题排查

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 打开项目报错 / 脚本无法加载 | 装了**标准版** Godot，不是 .NET 版 | 重新下载 `mono` 版（见 2.3） |
| C# 编译报错 / 游戏黑屏 | 没装 .NET SDK | 安装 .NET SDK 8.0（见 2.4） |
| 改完脚本没生效 | Godot C# 需要重新编译 | 点顶部 **Build** 按钮，或按 `Ctrl+B` |
| 提示 `rejected` / 推送被拒 | 远程有队友的新代码，你本地落后了 | 先 **拉取**，再 **推送**（不要强制推送） |
| 拉取时出现冲突标记 | 两人改了同一行 | 见第 6 章 |
| 第一次打开项目资源重新导入很慢 | 正常现象 | `.godot/` 缓存被忽略，每次克隆都要重新生成 |
| 场景文件 `.tscn` 打开报错 | 换行符异常 | 已配置 `.gitattributes` 自动处理；若仍报错，让主程检查 |

## 8. Godot C# 项目注意事项

1. **每次改完 C# 脚本要重新 Build**（`Ctrl+B`），改动才会生效
2. **新增 `.cs` 脚本后要先 Build 一次**，Godot 才能识别这个脚本
3. **类名必须和文件名一致**：例如文件 `Begin.cs` 里必须是 `public partial class Begin`
4. **`.cs.uid` 文件要正常提交**（Godot 4.4+ 生成的脚本唯一标识，删了会出问题）
5. **不要用记事本手改 `.tscn` 场景文件**，一律在 Godot 编辑器里操作
6. **素材统一放 `assets/`**，路径用相对路径（`res://assets/...`），这样换电脑不会失效
7. 导出游戏时：项目 → 导出 → 选 Windows Desktop（需要先下载导出模板）
